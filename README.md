# Dataset Catalog

A local registry of dataset fields and direct dependencies, requiring Python 3.10+ and no third-party packages. It records descriptions and schemas, not the dataset contents.

`python3 dataset_catalog.py describe orders` reads the included sample catalog. `python3 dataset_catalog.py dependencies daily_totals` returns the registered orders entry; queries are direct-only, not transitive. `python3 dataset_catalog.py impact orders` reports every registered dataset reachable downstream of `orders`, each with its shortest distance and propagation path; pass `--max-depth` (a positive integer) to limit how many dependency edges are traversed. `python3 dataset_catalog.py export --id daily_totals` writes `{"datasets": [...]}` containing the selected datasets together with every upstream dataset reachable through `depends_on`; repeat `--id` to select more (duplicates merge), or omit it to export the whole catalog. `python3 dataset_catalog.py search "daily amount"` performs a read-only keyword search: the query is split on Unicode whitespace (duplicate words ignored) and matched as literal casefolded substrings against dataset ids, descriptions and field names; every word must match the same dataset (possibly across its id, description and different field names). Pass `--field-type string|integer|number|boolean` to keep only datasets having at least one field of that type; the keyword still searches all field names. The output is an id-sorted array of `{"dataset": ..., "matched_fields": [...]}`, where `matched_fields` lists the fields hit by any query word in original order without duplicates (empty for an empty/whitespace query). Search never creates or modifies the catalog and never pulls in related datasets. Records are ordered dependencies first, breaking ties by id; exporting never modifies the catalog, and the output can be fed back to `register` entry by entry to rebuild the selected subset offline. The two sample descriptors are `samples/orders.json` and `samples/daily.json`.

To create a separate catalog, run `python3 dataset_catalog.py --catalog .state/catalog.json register samples/orders.json`, then register `samples/daily.json` in that same catalog. IDs must start with a lowercase letter and contain lowercase letters, digits, underscores or hyphens. Each dataset needs unique field names and field types string, integer, number or boolean. Dependencies must already be registered; registration cannot overwrite an existing ID. This append-only registration order prevents new entries from forming dependency cycles. There is no schema evolution, deletion or file ingestion command.

`DatasetCatalog.register`, `describe` and `dependencies` expose the same API; `DatasetCatalog.impact(identifier, max_depth=None)` returns the downstream list (each item holds the full `dataset` record, its shortest `distance` and the lexicographically smallest shortest `path`; `max_depth` must be `None` or a positive integer). `DatasetCatalog.export(identifiers=None)` returns `{"datasets": [...]}`: `None` exports everything, `[]` an empty array, otherwise a list of valid registered ids (strings matching the ID rule); duplicates merge and input order never affects the result. The result covers the selected datasets plus their full upstream closure along `depends_on`, each record appearing once, ordered with dependencies before dependents and lexicographically smallest id among currently-ready datasets. A missing dependency or a dependency cycle inside the selected closure raises `ValueError`; relations outside the selection are ignored. `DatasetCatalog.search(query="", field_type=None)` returns datasets sorted by id whose id, description or field names contain every query word as a casefolded literal substring; `field_type` (when one of string, integer, number, boolean) additionally requires a field of that type. Each result item holds the same full record as `describe` under `dataset` and `matched_fields` (the field names hit by any word, original order, no duplicates; empty when the query is blank). A non-string `query` or any other `field_type` value raises `ValueError`, even on an empty or missing catalog; search never writes to disk. CLI errors are JSON and exit 2. Run `python3 -B -m unittest -v` for persistence, dependency validation and CLI tests.
