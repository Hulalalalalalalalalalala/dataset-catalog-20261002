# Dataset Catalog

A local registry of dataset fields and direct dependencies, requiring Python 3.10+ and no third-party packages. It records descriptions and schemas, not the dataset contents.

`python3 dataset_catalog.py describe orders` reads the included sample catalog. `python3 dataset_catalog.py dependencies daily_totals` returns the registered orders entry; queries are direct-only, not transitive. `python3 dataset_catalog.py impact orders` reports every registered dataset reachable downstream of `orders`, each with its shortest distance and propagation path; pass `--max-depth` (a positive integer) to limit how many dependency edges are traversed. `python3 dataset_catalog.py export --id daily_totals` writes `{"datasets": [...]}` with the selected datasets plus every dataset reachable through their `depends_on` chains, in an order that always lists dependencies before their dependents (ties broken by ID); repeat `--id` to select several datasets, or omit it to export the whole catalog. The export never follows downstream edges and never modifies the catalog file; feeding its records one by one to `register` rebuilds an equivalent catalog offline. The two sample descriptors are `samples/orders.json` and `samples/daily.json`.

To create a separate catalog, run `python3 dataset_catalog.py --catalog .state/catalog.json register samples/orders.json`, then register `samples/daily.json` in that same catalog. IDs must start with a lowercase letter and contain lowercase letters, digits, underscores or hyphens. Each dataset needs unique field names and field types string, integer, number or boolean. Dependencies must already be registered; registration cannot overwrite an existing ID. This append-only registration order prevents new entries from forming dependency cycles. There is no schema evolution, deletion or file ingestion command.

`DatasetCatalog.register`, `describe` and `dependencies` expose the same API; `DatasetCatalog.impact(identifier, max_depth=None)` returns the downstream list (each item holds the full `dataset` record, its shortest `distance` and the lexicographically smallest shortest `path`; `max_depth` must be `None` or a positive integer). `DatasetCatalog.export(identifiers=None)` returns `{"datasets": [...]}` with full records identical to `describe`, ordered dependencies-first (ties broken by lexicographic ID) for the selected IDs and all of their transitive upstream dependencies; pass `None` for everything or an empty list for no datasets. It raises `ValueError` for a non-list argument, invalid or unknown IDs, missing dependencies within the selected closure, or dependency cycles; an empty string is treated as an invalid ID, not as select-all. CLI errors are JSON and exit 2. Run `python3 -B -m unittest -v` for persistence, dependency validation and CLI tests.
