# Dataset Catalog

A local registry of dataset fields and direct dependencies, requiring Python 3.10+ and no third-party packages. It records descriptions and schemas, not the dataset contents.

`python3 dataset_catalog.py describe orders` reads the included sample catalog. `python3 dataset_catalog.py dependencies daily_totals` returns the registered orders entry; queries are direct-only, not transitive. `python3 dataset_catalog.py impact orders` reports every registered dataset reachable downstream of `orders`, each with its shortest distance and propagation path; pass `--max-depth` (a positive integer) to limit how many dependency edges are traversed. `python3 dataset_catalog.py export --id daily_totals` writes `{"datasets": [...]}` containing the selected datasets together with every upstream dataset reachable through `depends_on`; repeat `--id` to select more (duplicates merge), or omit it to export the whole catalog. Records are ordered dependencies first, breaking ties by id; exporting never modifies the catalog, and the output can be fed back to `register` entry by entry to rebuild the selected subset offline. `python3 dataset_catalog.py import FILE` imports a whole export-shaped bundle (`{"datasets": [...]}`) in one batch into the catalog selected by `--catalog`; dependencies may point at already registered datasets or at other datasets in the same batch, descriptors may appear in any order, and only metadata is registered — dataset contents are never read. Any validation failure rejects the whole batch, leaves the catalog file untouched and never creates a missing file or its parent directories; CLI errors are JSON with exit code 2. `python3 dataset_catalog.py diff FILE` performs a read-only comparison: the catalog selected by `--catalog` is the before state and the `{"datasets": [...]}` snapshot in FILE is the complete after state (a partial export still represents the whole after catalog and is not padded with current records, and records matching by id are compared directly without import's existing-id conflict rule). It prints `{"added": [...], "removed": [...], "changed": [...]}`, each array sorted by dataset id; `added` and `removed` hold full normalized records found only on one side, while each `changed` item holds `id`, `before`, `after` and a lexicographically sorted `changed_keys` list, and unchanged same-id records are omitted (empty arrays are still returned). Snapshot descriptors follow the same normalization rules as registration, so description conversion, field filtering, dependency sorting and tag cleaning apply, unsaved extra properties and object key order are ignored, and tag spelling/order changes — including omitting `tags` versus `tags: []` — count as changes, while dataset or dependency ordering alone do not. The snapshot is validated as a self-contained catalog: dependencies may use forward references but must stay inside the snapshot, and a non-object snapshot, a missing or non-array `datasets` key, an invalid descriptor, a duplicate id, a duplicate or missing dependency, a self dependency or a cycle raises `ValueError` with no partial diff; an empty snapshot means the after state has no datasets, while a missing catalog file or one containing `{}` means an empty before state. The comparison never mutates the passed bundle, the catalog file or the snapshot file, never creates files or directories, never reads dataset contents, and an unreadable file, invalid JSON or failed validation prints JSON containing `error` and exits 2. `python3 dataset_catalog.py preview FILE` is a read-only change-impact preview with the same before/after snapshot semantics as `diff`: it prints `{"diff": {...}, "affected": [...]}`, where `diff` is exactly the object `diff` prints and `affected` lists every downstream dataset reached from a change source. Added and removed records and every `changed` record are change sources — a description-only or tags-only change propagates just like any other change — and when the diff is empty `affected` is `[]`. Each affected item (sorted by dataset id) holds only `id` and `causes`; a dataset appears once per side on which any change source reaches it along downstream edges, but a change source is never listed solely because it itself changed (it may still appear when another source reaches it). `causes` is sorted by source id and each cause holds only the source `id` plus `before` and `after`, the shortest propagation explanation on that side (positive edge `distance` and a `path` including source and target; ties choose the lexicographically smallest id sequence), or `null` when the source or target is absent or unreachable on that side; a cause with both sides `null` is omitted. The two sides are queried independently — a path valid only after the change is never stitched onto a before path — so a removed source can still affect retained or removed datasets in `before`, while an added source propagates only in `after`. Preview applies the snapshot validation of `diff` and additionally validates the current catalog's dependency graph: invalid descriptors, duplicate ids, duplicate or missing dependencies, self dependencies and cycles all raise `ValueError` with no partial result; a missing catalog file or `{}` is an empty catalog and an empty snapshot deletes every record. Preview never mutates its inputs, files or directories, never reads dataset contents, and its output does not depend on input ordering; file, JSON or validation failures print JSON containing `error` and exit 2. `python3 dataset_catalog.py search "daily amount"` performs a read-only keyword search over dataset ids, descriptions and field names (dependency ids and field type text are not searched); the query is optional and `--field-type string|integer|number|boolean` restricts results to datasets having at least one field of that type. `--tag TAG` (repeatable, one tag per flag) restricts results to datasets carrying every given tag. `--owner OWNER` restricts results to datasets whose owner matches the whole given string under Unicode casefold (no word splitting, substring or wildcard matching), applying the same trimming and nonempty rules as registration; datasets without an owner never match, and an invalid value errors before the catalog is read. The two sample descriptors are `samples/orders.json` and `samples/daily.json`.

To create a separate catalog, run `python3 dataset_catalog.py --catalog .state/catalog.json register samples/orders.json`, then register `samples/daily.json` in that same catalog. IDs must start with a lowercase letter and contain lowercase letters, digits, underscores or hyphens. Each dataset needs unique field names and field types string, integer, number or boolean. Dependencies must already be registered; registration cannot overwrite an existing ID. This append-only registration order prevents new entries from forming dependency cycles. There is no schema evolution, deletion or file ingestion command. A descriptor may also carry an optional `tags` list of strings: each tag is stripped of surrounding Unicode whitespace, must be nonempty, and duplicates are merged by Unicode casefold keeping the first spelling and order. Passing `"tags": []` stores an empty list; omitting the key stores no tags at all. A non-list value, a non-string member or an empty-after-strip tag raises `ValueError` and leaves the catalog untouched. A descriptor may also carry an optional single `owner` string: surrounding Unicode whitespace is stripped and the result must be nonempty, while the original casing and internal whitespace are kept; omitting the key stores no owner at all, and `null`, any non-string value or an empty-after-strip string raises `ValueError` and leaves the catalog untouched.

`DatasetCatalog.register`, `describe` and `dependencies` expose the same API; `DatasetCatalog.impact(identifier, max_depth=None)` returns the downstream list (each item holds the full `dataset` record, its shortest `distance` and the lexicographically smallest shortest `path`; `max_depth` must be `None` or a positive integer). `DatasetCatalog.export(identifiers=None)` returns `{"datasets": [...]}`: `None` exports everything, `[]` an empty array, otherwise a list of valid registered ids (strings matching the ID rule); duplicates merge and input order never affects the result. The result covers the selected datasets plus their full upstream closure along `depends_on`, each record appearing once, ordered with dependencies before dependents and lexicographically smallest id among currently-ready datasets. A missing dependency or a dependency cycle inside the selected closure raises `ValueError`; relations outside the selection are ignored. `DatasetCatalog.import_bundle(bundle)` accepts an object with the same `{"datasets": [...]}` shape `export` produces (any other top-level keys are ignored) and registers every descriptor in one transaction: each descriptor follows the same field, description, tags and duplicate-dependency rules as `register`, while dependencies may name either existing ids or other ids in the batch, in any order and including forward references. Duplicate ids inside the batch, ids already registered (even with identical content, which is never overwritten), unknown dependencies, self dependencies and batch-internal cycles, as well as a non-object bundle, a missing or non-array `datasets` key, and any descriptor that would fail `register`, all raise `ValueError` before anything is saved — the catalog file keeps its original contents and a missing catalog file (or its parent directories) is never created. On success it returns `{"datasets": [...]}` holding only the newly added, fully normalized records, ordered dependencies first with lexicographically-smallest-id tie-breaking, so input order never changes the result; `{"datasets": []}` returns an empty array and never writes; the passed-in object is never mutated. Afterwards the new records are immediately visible through `describe`, `dependencies`, `search`, `impact` and `export` with their existing semantics. Plain `register` still accepts exactly one descriptor whose dependencies are all already registered. `DatasetCatalog.diff_bundle(bundle)` is a read-only diff treating the catalog as the before state and the validated snapshot bundle as the complete after state (even a partial export is compared as a full catalog, never padded with current records, and same-name datasets are compared without import's existing-id conflict rule). It returns exactly the keys `added`, `removed`, `changed`, each array sorted by dataset id: `added` lists full normalized records only in the snapshot, `removed` full records only in the catalog, and each `changed` item holds `id`, the full `before` and `after` records and a lexicographically sorted `changed_keys`; unchanged same-id records are omitted and every key is present (as an empty array) when there are no results. Both sides go through registration's description conversion, field filtering, dependency sorting and tag cleaning, so unsaved extra properties and object key order are ignored, tag retention, spelling and order changes count (including omitted `tags` versus `tags: []`), while snapshot dataset order and dependency order never do. The snapshot is validated by the same descriptor rules but as a self-contained graph whose dependencies may include forward references but must point only inside the snapshot: a non-object bundle, missing or non-array `datasets`, invalid descriptors, duplicate ids, duplicate or missing dependencies, self dependencies and cycles all raise `ValueError` before any comparison, so no partial diff is returned; a missing catalog file or one containing `{}` is an empty before state. The call never mutates the passed bundle (deep copies are returned), never writes to or creates the catalog file or any parent directory, and never reads dataset contents; existing registration, import, export, describe, dependencies, search and impact behavior is unchanged. `DatasetCatalog.preview_bundle(bundle)` is a read-only preview that reuses `diff_bundle`'s snapshot semantics, normalization and validation, treating the catalog as before and the validated complete snapshot as after; it returns exactly `{"diff": ..., "affected": [...]}` where `diff` is the same object `diff_bundle` returns. Change sources are the ids of every added and removed record and every `changed` record (description- or tags-only changes included). `affected` is sorted by target id; each item holds only `id` and `causes`. A target appears once when any change source reaches it downstream on either side, except a source is never included merely for its own change (it may still appear through another source). `causes` is sorted by source id; each cause holds only the source `id` and a `before`/`after` pair. Each side is the shortest downstream propagation from that source in that side's graph — a positive integer edge `distance` and a `path` containing both source and target, choosing the lexicographically smallest id sequence among equal-distance paths — or `null` when the source or target does not exist on that side or is unreachable; a cause whose two sides are both `null` is omitted, and an empty diff yields `affected: []`. The before and after graphs are queried separately, so no path mixes states: removed sources propagate in `before` (to retained or removed targets), added sources only in `after`. Besides the snapshot validation, the current catalog is itself validated as a dependency graph; invalid descriptors, duplicate ids, duplicate or missing dependencies, self dependencies and cycles raise `ValueError` with no partial result; a missing catalog file or `{}` is an empty catalog and an empty snapshot removes everything. The call never mutates the bundle, catalog or snapshot file, never creates files or directories, and never reads dataset contents; the output is independent of input order. `DatasetCatalog.search(query="", field_type=None)` is read-only and returns a list sorted by dataset id; each item holds the same full record as `describe` under `dataset` and `matched_fields`, the field names hit by any query word in original field order without duplicates (empty when no field is hit or the query is empty). The query is split on Unicode whitespace, duplicate words do not change the result, and matching is literal substring matching after Unicode casefold — no regex or wildcards; every word must hit the same dataset, possibly across its id, description and different field names. An empty or whitespace-only query imposes no keyword restriction; when `field_type` is one of string, integer, number or boolean the dataset must have at least one field of that type while keywords still search every field name. A non-string query, or a `field_type` other than `None` and the four supported types, raises `ValueError` — arguments are validated before the catalog is read, so a missing or empty catalog still yields `[]` and never creates a file. `DatasetCatalog.search(query="", field_type=None, tags=None)` also accepts `tags`: `None` or `[]` imposes no tag restriction, while a nonempty list requires the dataset to carry every listed tag. Tags follow the same type, stripping and dedup rules as registration, are validated before the catalog is read, and match whole tags by Unicode casefold only — no word splitting, substring, regex or wildcard matching. Records registered before tags existed are treated as having no tags and are never rewritten by a search. An optional `owner` keyword (and CLI `--owner OWNER`) follows the same pattern: `None` imposes no restriction, a given value is trimmed with the registration rules (a non-string or empty-after-strip value, including `null`, raises `ValueError` before the catalog is read) and matches only a stored owner whose complete string compares equal after Unicode casefold — no word splitting, substring or wildcard matching. Records without an owner never match an owner filter, are never rewritten, and still participate normally when no owner filter is given; owner is never part of the keyword scope, so keywords still search only id, description and field names and `matched_fields` reflects keyword hits only. Keyword, field-type, tag and owner conditions all apply together. `describe`, `dependencies`, `impact`, `search` results and `export` all carry the stored `owner` on the full record (the key is simply absent when unset), and an exported bundle restores owners through the existing `import_bundle` entry with the same validation — a rejected single registration or whole batch writes nothing, leaves the catalog bytes untouched, never creates a missing file or parent directories, and never mutates the passed descriptor or bundle. `diff_bundle`/`preview_bundle` apply the same owner normalization to both snapshot and current sides: adding an owner, removing it or changing its cleaned spelling reports `owner` in `changed_keys`, while a difference in surrounding whitespace alone does not; an owner-only change is a change source for the impact preview exactly like any other change, and an invalid owner on either side raises `ValueError` with no partial result and without mutating inputs or files. CLI errors are JSON and exit 2. Run `python3 -B -m unittest -v` for persistence, dependency validation and CLI tests.
