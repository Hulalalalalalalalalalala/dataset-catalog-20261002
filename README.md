# Dataset Catalog

A local registry of dataset fields and direct dependencies, requiring Python 3.10+ and no third-party packages. It records descriptions and schemas, not the dataset contents.

`python3 dataset_catalog.py describe orders` reads the included sample catalog. `python3 dataset_catalog.py dependencies daily_totals` returns the registered orders entry; queries are direct-only, not transitive. `python3 dataset_catalog.py impact orders` reports every registered dataset reachable downstream of `orders`, each with its shortest distance and propagation path; pass `--max-depth` (a positive integer) to limit how many dependency edges are traversed. `python3 dataset_catalog.py export --id daily_totals` writes `{"datasets": [...]}` containing the selected datasets together with every upstream dataset reachable through `depends_on`; repeat `--id` to select more (duplicates merge), or omit it to export the whole catalog. Records are ordered dependencies first, breaking ties by id; exporting never modifies the catalog, and the output can be fed back to `register` entry by entry to rebuild the selected subset offline. `python3 dataset_catalog.py import FILE` reads a bundle with that same structure and registers every dataset in one batch: dependencies may point at already-registered datasets or at other datasets in the same file in any order, so a whole export can be rebuilt at once regardless of record order. Only metadata is registered, never dataset contents. `python3 dataset_catalog.py search "daily amount"` performs a read-only keyword search over dataset ids, descriptions and field names (dependency ids and field type text are not searched); the query is optional and `--field-type string|integer|number|boolean` restricts results to datasets having at least one field of that type. `--tag TAG` (repeatable, one tag per flag) restricts results to datasets carrying every given tag. The two sample descriptors are `samples/orders.json` and `samples/daily.json`.

To create a separate catalog, run `python3 dataset_catalog.py --catalog .state/catalog.json register samples/orders.json`, then register `samples/daily.json` in that same catalog. IDs must start with a lowercase letter and contain lowercase letters, digits, underscores or hyphens. Each dataset needs unique field names and field types string, integer, number or boolean. Dependencies must already be registered; registration cannot overwrite an existing ID. This append-only registration order prevents new entries from forming dependency cycles. There is no schema evolution, deletion or file ingestion command. A descriptor may also carry an optional `tags` list of strings: each tag is stripped of surrounding Unicode whitespace, must be nonempty, and duplicates are merged by Unicode casefold keeping the first spelling and order. Passing `"tags": []` stores an empty list; omitting the key stores no tags at all. A non-list value, a non-string member or an empty-after-strip tag raises `ValueError` and leaves the catalog untouched.

`DatasetCatalog.register`, `describe` and `dependencies` expose the same API; `DatasetCatalog.impact(identifier, max_depth=None)` returns the downstream list (each item holds the full `dataset` record, its shortest `distance` and the lexicographically smallest shortest `path`; `max_depth` must be `None` or a positive integer). `DatasetCatalog.export(identifiers=None)` returns `{"datasets": [...]}`: `None` exports everything, `[]` an empty array, otherwise a list of valid registered ids (strings matching the ID rule); duplicates merge and input order never affects the result. The result covers the selected datasets plus their full upstream closure along `depends_on`, each record appearing once, ordered with dependencies before dependents and lexicographically smallest id among currently-ready datasets. A missing dependency or a dependency cycle inside the selected closure raises `ValueError`; relations outside the selection are ignored. `DatasetCatalog.import_bundle(bundle)` performs the inverse operation in one transactional batch. The top-level value must be an object containing a `datasets` array; any other top-level keys are ignored. Each descriptor follows exactly the same field, description, tag and dependency rules as `register`, except dependencies may also name other ids in the same batch. Duplicate ids within the batch, ids already registered (no overwrite, even for identical content), missing dependencies, self-dependencies and dependency cycles raise `ValueError`; so do a non-object top-level value, a missing or non-array `datasets`, and any descriptor that violates the registration rules. Every descriptor is validated and the batch is topologically ordered before anything is written, so any failure leaves the existing catalog file byte-for-byte unchanged and never creates the file or its parent directories. On success it returns `{"datasets": [...]}` holding only the newly added, fully normalized records — never the pre-existing dependencies — ordered dependencies first, breaking ties among all currently-ready datasets by lexicographic id, so input order never changes the result. An empty array returns `{"datasets": []}` without touching or creating the file, and the passed-in object is never modified. New records are immediately visible to `describe`, `dependencies`, `search`, `impact` and `export`, each keeping its existing semantics. `register` itself still accepts only a single descriptor whose dependencies are already registered. On the command line `import FILE` prints the same JSON and exits 0; an unreadable file, invalid JSON or failed batch validation prints a JSON object containing `error` and exits 2. `DatasetCatalog.search(query="", field_type=None)` is read-only and returns a list sorted by dataset id; each item holds the same full record as `describe` under `dataset` and `matched_fields`, the field names hit by any query word in original field order without duplicates (empty when no field is hit or the query is empty). The query is split on Unicode whitespace, duplicate words do not change the result, and matching is literal substring matching after Unicode casefold — no regex or wildcards; every word must hit the same dataset, possibly across its id, description and different field names. An empty or whitespace-only query imposes no keyword restriction; when `field_type` is one of string, integer, number or boolean the dataset must have at least one field of that type while keywords still search every field name. A non-string query, or a `field_type` other than `None` and the four supported types, raises `ValueError` — arguments are validated before the catalog is read, so a missing or empty catalog still yields `[]` and never creates a file. `DatasetCatalog.search(query="", field_type=None, tags=None)` also accepts `tags`: `None` or `[]` imposes no tag restriction, while a nonempty list requires the dataset to carry every listed tag. Tags follow the same type, stripping and dedup rules as registration, are validated before the catalog is read, and match whole tags by Unicode casefold only — no word splitting, substring, regex or wildcard matching. Records registered before tags existed are treated as having no tags and are never rewritten by a search. Keyword, field-type and tag conditions all apply together; keywords still search only the original scopes and `matched_fields` still reflects keyword hits only. CLI errors are JSON and exit 2. Run `python3 -B -m unittest -v` for persistence, dependency validation and CLI tests.
