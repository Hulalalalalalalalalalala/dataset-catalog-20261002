# Dataset Catalog

A local registry of dataset fields and direct dependencies, requiring Python 3.10+ and no third-party packages. It records descriptions and schemas, not the dataset contents.

`python3 dataset_catalog.py describe orders` reads the included sample catalog. `python3 dataset_catalog.py dependencies daily_totals` returns the registered orders entry; queries are direct-only, not transitive. `python3 dataset_catalog.py impact orders` reports every registered dataset reachable downstream of `orders`, each with its shortest distance and propagation path; pass `--max-depth` (a positive integer) to limit how many dependency edges are traversed. `python3 dataset_catalog.py upstream daily_totals` is the mirror query along `depends_on`: it lists the direct and indirect upstream datasets of `daily_totals` (never the start itself), each item holding only `dataset` (the same full record `describe` prints), `distance` (the fewest dependency edges from the start) and `path` (the id sequence from the start to that upstream, both ends included). Every upstream appears once, sorted by distance and then by dataset id; ties between equally short paths choose the lexicographically smallest id sequence, and catalog or dependency ordering never changes the result. `--max-depth` (a positive decimal integer) keeps only records whose shortest distance stays within the limit, and omitting it returns the whole upstream closure; a registered dataset with no upstream yields `[]`. The start and its entire upstream closure are validated like a self-contained catalog — an invalid start id or depth, an unregistered start, a non-object catalog, and inside the closure an invalid descriptor, a record key disagreeing with its id, a duplicate or missing dependency, a self dependency or a cycle all raise `ValueError` with no partial result, and a depth limit never hides errors in farther upstream records, while records and relations outside the closure are ignored. Argument formats are validated before the catalog is read; a missing catalog file or one containing `{}` is an empty catalog, an unreadable file raises `OSError` and invalid JSON raises `json.JSONDecodeError`. The query never modifies or creates files or directories and never reads dataset contents. `python3 dataset_catalog.py export --id daily_totals` writes `{"datasets": [...]}` containing the selected datasets together with every upstream dataset reachable through `depends_on`; repeat `--id` to select more (duplicates merge), or omit it to export the whole catalog. Records are ordered dependencies first, breaking ties by id; exporting never modifies the catalog, and the output can be fed back to `register` entry by entry to rebuild the selected subset offline. `python3 dataset_catalog.py import FILE` imports a whole export-shaped bundle (`{"datasets": [...]}`) in one batch into the catalog selected by `--catalog`; dependencies may point at already registered datasets or at other datasets in the same batch, descriptors may appear in any order, and only metadata is registered — dataset contents are never read. Any validation failure rejects the whole batch, leaves the catalog file untouched and never creates a missing file or its parent directories; CLI errors are JSON with exit code 2. `python3 dataset_catalog.py diff FILE` performs a read-only comparison: the catalog selected by `--catalog` is the before state and the `{"datasets": [...]}` snapshot in FILE is the complete after state (a partial export still represents the whole after catalog and is not padded with current records, and records matching by id are compared directly without import's existing-id conflict rule). It prints `{"added": [...], "removed": [...], "changed": [...]}`, each array sorted by dataset id; `added` and `removed` hold full normalized records found only on one side, while each `changed` item holds `id`, `before`, `after` and a lexicographically sorted `changed_keys` list, and unchanged same-id records are omitted (empty arrays are still returned). Snapshot descriptors follow the same normalization rules as registration, so description conversion, field filtering, dependency sorting, tag cleaning and owner cleaning apply, unsaved extra properties and object key order are ignored, and tag spelling/order changes — including omitting `tags` versus `tags: []` — and owner changes (adding, removing, or changing the cleaned spelling, but not surrounding whitespace alone) count as changes, while dataset or dependency ordering alone do not. The snapshot is validated as a self-contained catalog: dependencies may use forward references but must stay inside the snapshot, and a non-object snapshot, a missing or non-array `datasets` key, an invalid descriptor, a duplicate id, a duplicate or missing dependency, a self dependency or a cycle raises `ValueError` with no partial diff; an empty snapshot means the after state has no datasets, while a missing catalog file or one containing `{}` means an empty before state. The comparison never mutates the passed bundle, the catalog file or the snapshot file, never creates files or directories, never reads dataset contents, and an unreadable file, invalid JSON or failed validation prints JSON containing `error` and exits 2. `python3 dataset_catalog.py preview FILE` is a read-only change-impact preview with the same before/after snapshot semantics as `diff`: it prints `{"diff": {...}, "affected": [...]}`, where `diff` is exactly the object `diff` prints and `affected` lists every downstream dataset reached from a change source. Added and removed records and every `changed` record are change sources — a description-only, tags-only or owner-only change propagates just like any other change — and when the diff is empty `affected` is `[]`. Each affected item (sorted by dataset id) holds only `id` and `causes`; a dataset appears once per side on which any change source reaches it along downstream edges, but a change source is never listed solely because it itself changed (it may still appear when another source reaches it). `causes` is sorted by source id and each cause holds only the source `id` plus `before` and `after`, the shortest propagation explanation on that side (positive edge `distance` and a `path` including source and target; ties choose the lexicographically smallest id sequence), or `null` when the source or target is absent or unreachable on that side; a cause with both sides `null` is omitted. The two sides are queried independently — a path valid only after the change is never stitched onto a before path — so a removed source can still affect retained or removed datasets in `before`, while an added source propagates only in `after`. Preview applies the snapshot validation of `diff` and additionally validates the current catalog's dependency graph: invalid descriptors, duplicate ids, duplicate or missing dependencies, self dependencies and cycles all raise `ValueError` with no partial result; a missing catalog file or `{}` is an empty catalog and an empty snapshot deletes every record. Preview never mutates its inputs, files or directories, never reads dataset contents, and its output does not depend on input ordering; file, JSON or validation failures print JSON containing `error` and exit 2. `python3 dataset_catalog.py schema-diff FILE` is a read-only field-change review with the same before/after snapshot semantics as `diff` and `preview`: the catalog selected by `--catalog` is the before state and the complete `{"datasets": [...]}` snapshot in FILE is the after state (a partial export is still the whole after catalog and is not padded, an empty snapshot means no datasets remain, and a missing catalog file or one containing `{}` means an empty before state). It prints `{"changes": [...]}`, sorted by dataset id and containing only records whose fields changed; records without a field change are omitted and when nothing changed it prints `{"changes": []}`. Each item holds only `id`, `added_fields`, `removed_fields`, `type_changes` and `breaking`: the first two arrays hold `name`/`type` pairs and `type_changes` holds `name`/`before`/`after` pairs giving the field name and its types on each side, and all three arrays are sorted by field name in Unicode code-point order (empty arrays are still present). Every field of a newly added dataset counts as added and every field of a deleted dataset counts as removed; same-named fields pair by exact name with no whitespace stripping or case folding, so a rename appears as the old field removed and the new field added, and changes limited to field order, description, tags, owner or dependencies produce no item. `breaking` is this feature's fixed review verdict — `true` whenever a field is removed or a type changes other than integer to number (the only non-breaking type change), and `false` otherwise, so a plain integer-to-number widening alone is not breaking. Both sides use `preview`'s normalization and full dependency-graph validation, so invalid descriptors, duplicate ids, duplicate or missing dependencies, self dependencies and cycles raise `ValueError` with no partial result, even when only other metadata would change; an unreadable file raises `OSError` and invalid JSON raises `json.JSONDecodeError`, and every such CLI failure prints JSON containing `error` and exits 2. The command never mutates the passed bundle or any file, never creates directories and never reads dataset contents. `python3 dataset_catalog.py apply FILE` commits the `{"datasets": [...]}` snapshot in FILE as the complete new state of the catalog selected by `--catalog`: records matching by id are replaced, new ids are added, records absent from the snapshot are removed (a partial export still represents the whole target catalog and is not padded with current records), and an empty snapshot clears the catalog. It prints the same `{"added": [...], "removed": [...], "changed": [...]}` object `diff` would have printed before the commit. The snapshot follows `diff`'s normalization and validation rules and the current catalog is validated with `preview`'s rules; any validation failure rejects the whole apply, leaves the catalog file untouched and never creates a missing file or its parent directories. The commit is all-or-nothing: when there are differences the full set of normalized records is saved atomically in the existing storage format (creating parent directories as needed), a save failure raises `OSError` with the original file contents preserved and a previously missing file still absent, and when there is no difference nothing is written or created. Pass `--expected FILE` to declare the catalog state the change was based on: FILE holds a `{"datasets": [...]}` snapshot that is validated and normalized exactly like the target snapshot and compared against the current catalog by dataset id (dataset order, object key order, unsaved properties and dependency order are ignored, while field order, tag retention/spelling/order and cleaned owner spelling count); unless the two match, the apply is rejected with `catalog does not match expected snapshot` — even when the target equals the current state — and an empty expected snapshot matches only an empty catalog. A `null` expected file is an invalid snapshot. Only metadata is handled — dataset contents are never read — and after a successful apply every query and export immediately reflects the new state. An unreadable file, invalid JSON, failed validation or a failed save prints JSON containing `error` and exits 2. `python3 dataset_catalog.py search "daily amount"` performs a read-only keyword search over dataset ids, descriptions and field names (dependency ids and field type text are not searched); the query is optional and `--field-type string|integer|number|boolean` restricts results to datasets having at least one field of that type. `--tag TAG` (repeatable, one tag per flag) restricts results to datasets carrying every given tag. `--owner OWNER` restricts results to datasets whose `owner` string matches the given value in full after Unicode casefold (surrounding Unicode whitespace is stripped first); records without an owner never match an owner filter, and the owner value is not searched by keywords. The two sample descriptors are `samples/orders.json` and `samples/daily.json`.

To create a separate catalog, run `python3 dataset_catalog.py --catalog .state/catalog.json register samples/orders.json`, then register `samples/daily.json` in that same catalog. IDs must start with a lowercase letter and contain lowercase letters, digits, underscores or hyphens. Each dataset needs unique field names and field types string, integer, number or boolean. Dependencies must already be registered; registration cannot overwrite an existing ID. This append-only registration order prevents new entries from forming dependency cycles. Registration stays append-only with no per-record update or delete — replacing or removing records happens only by applying a complete snapshot with `apply` — and there is no file ingestion command. A descriptor may also carry an optional `tags` list of strings: each tag is stripped of surrounding Unicode whitespace, must be nonempty, and duplicates are merged by Unicode casefold keeping the first spelling and order. Passing `"tags": []` stores an empty list; omitting the key stores no tags at all. A non-list value, a non-string member or an empty-after-strip tag raises `ValueError` and leaves the catalog untouched. A descriptor may also carry an optional `owner` string naming the single responsible owner: surrounding Unicode whitespace is stripped and the result must be nonempty, after which the cleaned value is stored as given, preserving original casing and internal whitespace. Omitting the key stores no `owner` at all; `null` or any non-string value and an empty-after-strip string raise `ValueError` and leave the catalog untouched.

`DatasetCatalog.register`, `describe` and `dependencies` expose the same API; `DatasetCatalog.impact(identifier, max_depth=None)` returns the downstream list (each item holds the full `dataset` record, its shortest `distance` and the lexicographically smallest shortest `path`; `max_depth` must be `None` or a positive integer). `DatasetCatalog.upstream(identifier, max_depth=None)` is the mirror query along `depends_on`: it returns the direct and indirect upstream datasets of `identifier` (excluding the start), each item holding only `dataset` (the same full record `describe` returns), `distance` (the fewest dependency edges) and `path` (the id sequence from the start to that upstream, both ends included), sorted by distance and then dataset id, with ties between equally short paths choosing the lexicographically smallest id sequence; `max_depth` must be `None` or a non-boolean positive integer and keeps only records within that shortest distance. The start and its full upstream closure are validated (invalid start id or depth, unregistered start, non-object catalog, and in-closure invalid descriptors, key/id mismatches, duplicate or missing dependencies, self dependencies and cycles all raise `ValueError` with no partial result, and a depth limit never skips farther-upstream validation), records outside the closure are ignored, argument formats are checked before the catalog is read, and the query never writes or creates files. `DatasetCatalog.export(identifiers=None)` returns `{"datasets": [...]}`: `None` exports everything, `[]` an empty array, otherwise a list of valid registered ids (strings matching the ID rule); duplicates merge and input order never affects the result. The result covers the selected datasets plus their full upstream closure along `depends_on`, each record appearing once, ordered with dependencies before dependents and lexicographically smallest id among currently-ready datasets. A missing dependency or a dependency cycle inside the selected closure raises `ValueError`; relations outside the selection are ignored. `DatasetCatalog.import_bundle(bundle)` accepts an object with the same `{"datasets": [...]}` shape `export` produces (any other top-level keys are ignored) and registers every descriptor in one transaction: each descriptor follows the same field, description, tags, owner and duplicate-dependency rules as `register`, while dependencies may name either existing ids or other ids in the batch, in any order and including forward references. Duplicate ids inside the batch, ids already registered (even with identical content, which is never overwritten), unknown dependencies, self dependencies and batch-internal cycles, as well as a non-object bundle, a missing or non-array `datasets` key, and any descriptor that would fail `register`, all raise `ValueError` before anything is saved — the catalog file keeps its original contents and a missing catalog file (or its parent directories) is never created. On success it returns `{"datasets": [...]}` holding only the newly added, fully normalized records, ordered dependencies first with lexicographically-smallest-id tie-breaking, so input order never changes the result; `{"datasets": []}` returns an empty array and never writes; the passed-in object is never mutated. Afterwards the new records are immediately visible through `describe`, `dependencies`, `search`, `impact` and `export` with their existing semantics. Plain `register` still accepts exactly one descriptor whose dependencies are all already registered. `DatasetCatalog.diff_bundle(bundle)` is a read-only diff treating the catalog as the before state and the validated snapshot bundle as the complete after state (even a partial export is compared as a full catalog, never padded with current records, and same-name datasets are compared without import's existing-id conflict rule). It returns exactly the keys `added`, `removed`, `changed`, each array sorted by dataset id: `added` lists full normalized records only in the snapshot, `removed` full records only in the catalog, and each `changed` item holds `id`, the full `before` and `after` records and a lexicographically sorted `changed_keys`; unchanged same-id records are omitted and every key is present (as an empty array) when there are no results. Both sides go through registration's description conversion, field filtering, dependency sorting, tag cleaning and owner cleaning, so unsaved extra properties and object key order are ignored, tag retention, spelling and order changes count (including omitted `tags` versus `tags: []`), while snapshot dataset order and dependency order never do. Adding or removing an `owner`, or changing its cleaned spelling, counts as a change with `owner` in `changed_keys`; a value differing only in surrounding Unicode whitespace (case and internal whitespace unchanged) does not. The snapshot is validated by the same descriptor rules but as a self-contained graph whose dependencies may include forward references but must point only inside the snapshot: a non-object bundle, missing or non-array `datasets`, invalid descriptors, duplicate ids, duplicate or missing dependencies, self dependencies and cycles all raise `ValueError` before any comparison, so no partial diff is returned; a missing catalog file or one containing `{}` is an empty before state. The call never mutates the passed bundle (deep copies are returned), never writes to or creates the catalog file or any parent directory, and never reads dataset contents; existing registration, import, export, describe, dependencies, search and impact behavior is unchanged. `DatasetCatalog.preview_bundle(bundle)` is a read-only preview that reuses `diff_bundle`'s snapshot semantics, normalization and validation, treating the catalog as before and the validated complete snapshot as after; it returns exactly `{"diff": ..., "affected": [...]}` where `diff` is the same object `diff_bundle` returns. Change sources are the ids of every added and removed record and every `changed` record (description-, tags- or owner-only changes included). `affected` is sorted by target id; each item holds only `id` and `causes`. A target appears once when any change source reaches it downstream on either side, except a source is never included merely for its own change (it may still appear through another source). `causes` is sorted by source id; each cause holds only the source `id` and a `before`/`after` pair. Each side is the shortest downstream propagation from that source in that side's graph — a positive integer edge `distance` and a `path` containing both source and target, choosing the lexicographically smallest id sequence among equal-distance paths — or `null` when the source or target does not exist on that side or is unreachable; a cause whose two sides are both `null` is omitted, and an empty diff yields `affected: []`. The before and after graphs are queried separately, so no path mixes states: removed sources propagate in `before` (to retained or removed targets), added sources only in `after`. Besides the snapshot validation, the current catalog is itself validated as a dependency graph; invalid descriptors, duplicate ids, duplicate or missing dependencies, self dependencies and cycles raise `ValueError` with no partial result; a missing catalog file or `{}` is an empty catalog and an empty snapshot removes everything. The call never mutates the bundle, catalog or snapshot file, never creates files or directories, and never reads dataset contents; the output is independent of input order. `DatasetCatalog.schema_diff_bundle(bundle)` is a read-only review of field-level changes using the same complete-before/current-and-complete-after/snapshot semantics, normalization and two-sided dependency-graph validation as `preview_bundle`: the snapshot is validated as a self-contained graph and the current catalog is validated too, so invalid descriptors, duplicate ids, duplicate or missing dependencies, self dependencies and cycles raise `ValueError` before any comparison, even when the only difference would be other metadata; a missing catalog file or `{}` is an empty catalog and an empty snapshot removes everything. It returns exactly `{"changes": [...]}`, sorted by dataset id, listing only records with field changes (no field change anywhere yields `{"changes": []}`); each item holds exactly `id`, `added_fields`, `removed_fields`, `type_changes` and `breaking`. `added_fields` and `removed_fields` hold `name`/`type` pairs and `type_changes` holds `name`/`before`/`after` pairs with the field name and its before and after types; all three arrays are sorted by field name in Unicode code-point order and are always present (as empty arrays). All fields of an added dataset count as added and all fields of a removed dataset count as removed; same-named fields are paired by their exact original names with no stripping or case folding, so a renaming is reported as one removal plus one addition. Differences limited to field order, description, tags, owner or dependencies produce no item (the field-order rule belongs only to the original `diff_bundle` comparison, which is unchanged). `breaking` is the feature's fixed verdict: `true` when at least one field is removed or at least one type change is not integer-to-number, and `false` otherwise — integer widening to number alone is therefore not breaking. The call never mutates the passed bundle or the catalog file, never creates files or directories, and never reads dataset contents; mutating the returned object affects neither the input bundle nor later queries. `DatasetCatalog.apply_bundle(bundle, expected_bundle=None)` commits a validated snapshot bundle as the complete catalog state — same-id records are replaced, new ids are added, records missing from the snapshot are removed, and an empty snapshot clears the catalog — and returns the pre-commit diff exactly as `diff_bundle` would have returned it (the `added`/`removed`/`changed` arrays sorted by id, with full before/after records and `changed_keys`). Normalization and snapshot validation match `diff_bundle`, the current catalog is validated with `preview_bundle`'s rules, and a missing catalog file or `{}` is an empty before state; any validation failure raises `ValueError` before anything is written, so the catalog file keeps its original contents and a missing file or its parent directories are never created. The commit is all-or-nothing: with differences the full set of normalized records is saved atomically in the existing storage format (parent directories are created as needed), a save failure raises `OSError` leaving the original file untouched and a previously missing file still absent, and an empty diff returns the three empty arrays without writing a file or creating directories. When `expected_bundle` is not `None` it is validated with the same snapshot rules as the target and compared against the current catalog read for this call — normalized records aligned by dataset id, ignoring dataset order, object key order, unsaved properties and dependency order, while field order, tag retention/spelling/order and cleaned owner spelling count; a mismatch raises `ValueError("catalog does not match expected snapshot")` before anything is written, even when the target equals the current state, and an empty expected snapshot matches only an empty catalog. The call never mutates the passed bundle, mutating the returned records affects neither the input nor the saved catalog, and afterwards `describe`, `dependencies`, `search`, `impact` and `export` immediately reflect the new state; existing registration, import, export, diff and preview behavior is unchanged. `DatasetCatalog.search(query="", field_type=None)` is read-only and returns a list sorted by dataset id; each item holds the same full record as `describe` under `dataset` and `matched_fields`, the field names hit by any query word in original field order without duplicates (empty when no field is hit or the query is empty). The query is split on Unicode whitespace, duplicate words do not change the result, and matching is literal substring matching after Unicode casefold — no regex or wildcards; every word must hit the same dataset, possibly across its id, description and different field names. An empty or whitespace-only query imposes no keyword restriction; when `field_type` is one of string, integer, number or boolean the dataset must have at least one field of that type while keywords still search every field name. A non-string query, or a `field_type` other than `None` and the four supported types, raises `ValueError` — arguments are validated before the catalog is read, so a missing or empty catalog still yields `[]` and never creates a file. `DatasetCatalog.search(query="", field_type=None, tags=None, owner=None)` also accepts `tags`: `None` or `[]` imposes no tag restriction, while a nonempty list requires the dataset to carry every listed tag. Tags follow the same type, stripping and dedup rules as registration, are validated before the catalog is read, and match whole tags by Unicode casefold only — no word splitting, substring, regex or wildcard matching. `owner=None` imposes no owner restriction; any other value is stripped of surrounding Unicode whitespace under the same nonempty-string rules as registration and must equal the record's stored owner in full after Unicode casefold — no word splitting, substring or wildcard matching. Records without an owner never match an owner filter; the owner filter is validated before the catalog is read. Records registered before owners existed are treated as having no owner and are never rewritten by a search. Keyword, field-type, tag and owner conditions all apply together; keywords still search only the original scopes (owner is not a keyword scope) and `matched_fields` still reflects keyword hits only. CLI errors are JSON and exit 2. Run `python3 -B -m unittest -v` for persistence, dependency validation and CLI tests.
