Install
python3 --version
Python 3.10 or newer; no external dependencies.

Start
python3 dataset_catalog.py describe orders
Prints the sample orders field schema.

Smoke Test
python3 dataset_catalog.py dependencies daily_totals
Returns orders as the only direct dependency.
python3 dataset_catalog.py impact orders
Returns daily_totals at distance 1 with path ["orders","daily_totals"].
python3 dataset_catalog.py upstream daily_totals
Returns orders at distance 1 with path ["daily_totals","orders"]; direct and indirect upstream,
sorted by distance then id, with --max-depth limiting the shortest distance; read-only, errors exit 2.
python3 dataset_catalog.py common-upstream --id orders --id daily_totals
Returns only orders: [{"dataset": orders record, "targets": [
  {"id":"daily_totals","distance":1,"path":["daily_totals","orders"]},
  {"id":"orders","distance":0,"path":["orders"]}]}]; repeat --id for more targets (duplicates merge,
at least two distinct ids), sources sort by id and targets sort by id, a candidate another shared
source depends on (even transitively) is omitted, independent common sources are all kept,
and no shared source prints []; read-only, errors exit 2.
python3 dataset_catalog.py between orders daily_totals
Returns {"datasets":[orders record, daily_totals record],"edges":[{"source":"orders","target":"daily_totals"}]}:
every node and edge on any directed SOURCE->TARGET path (all branches and path lengths, no path
enumeration), datasets sorted by id and edges sorted by source then target; the same id for both
ends returns that record and empty edges, registered but unreachable ends return two empty arrays,
the whole catalog is validated even outside the chain (key/id mismatch included); read-only,
errors exit 2.
python3 dataset_catalog.py critical orders daily_totals
Returns [daily_totals record, orders record]: the datasets every directed SOURCE->TARGET path
passes through (full describe records, each once, sorted by id, no path enumeration); both ends
are included when reachable, the same registered id for both ends returns that one record,
registered but unreachable ends return [], and the reversed direction is judged independently;
the whole catalog is validated even outside the queried paths; read-only, errors exit 2.
python3 dataset_catalog.py export --id daily_totals
Returns {"datasets":[orders record, daily_totals record]}, dependencies first.
python3 dataset_catalog.py export-csv --id daily_totals
Prints the field-level CSV data dictionary; fixed header
dataset_id,description,owner,tags,depends_on,field_name,field_type, one row per field in registered
field order with dataset metadata repeated on each row. It reuses export's --catalog, repeatable
--id and selection semantics (None = all, [] = empty, duplicate ids merge, full upstream closure
included, input order irrelevant); datasets stay dependencies first. Missing owner is an empty cell,
missing tags is []; tags and depends_on are compact JSON arrays preserving Chinese (tags in stored
order, dependencies sorted by id). Cells with commas, double quotes or newlines are double quoted
with inner quotes doubled, and newlines in field names or descriptions pass through; every line ends
with \n. An empty catalog or empty selection prints only the terminated header; read-only, errors
print JSON containing only error and exit 2.
python3 dataset_catalog.py search "daily amount"
Returns only orders with matched_fields ["amount"]; search is read-only.
python3 dataset_catalog.py search --field-type integer
Lists datasets having an integer field; an omitted query means no keyword restriction.
python3 dataset_catalog.py search amount --upstream-of daily_totals
Searches only the start dataset and its direct and indirect upstream along depends_on; returns
only orders (merged upstream is searched once and the start need not match); search total with
--upstream-of orders returns []; keywords and the other filters keep their semantics in range,
key and dependency order never change the result, and omitting the flag searches the whole
catalog; the closure is validated like upstream even when filters hide the bad record; an
illegal or unregistered --upstream-of id, invalid JSON or an unreadable file exits 2 with error.
python3 dataset_catalog.py diff FILE
Compares the catalog (before) with a {"datasets":[...]} snapshot file (after, treated as complete)
and prints {"added":[...],"removed":[...],"changed":[...]} sorted by id; read-only, errors exit 2.
python3 dataset_catalog.py preview FILE
Prints {"diff":{...},"affected":[...]}: the diff result plus every downstream dataset reached from
an added, removed or changed source, with lexicographically-smallest shortest before/after paths;
read-only, errors exit 2.
python3 dataset_catalog.py schema-diff FILE
Reviews read-only field changes against a complete {"datasets":[...]} snapshot (catalog = before)
and prints {"changes":[...]} sorted by dataset id; each item holds only id, added_fields,
removed_fields (name/type pairs), type_changes (name/before/after) and breaking, arrays sorted by
field name; breaking is true for any removed field or non-integer-to-number type change;
read-only, errors exit 2.
python3 dataset_catalog.py apply FILE
Commits a {"datasets":[...]} snapshot file as the complete catalog state (same-id records replaced,
new ids added, absent records removed) and prints the pre-commit
{"added":[...],"removed":[...],"changed":[...]} diff; all-or-nothing, errors exit 2.
Pass --expected FILE to require the current catalog to match that expected snapshot first;
a mismatch prints {"error":"catalog does not match expected snapshot"} and exits 2.
python3 dataset_catalog.py merge FILE
Incrementally merges a {"datasets":[...]} bundle file into the catalog: listed datasets are
added or fully replace the same-id record (omitting owner/tags removes them, omitting
depends_on stores []), unlisted records are kept and nothing is deleted. Prints the same
{"added":[...],"removed":[...],"changed":[...]} diff as diff (removed always empty); an empty
or no-change batch prints three empty arrays without writing. The whole current catalog and
the merged dependency graph are validated before the atomic commit; errors exit 2.
